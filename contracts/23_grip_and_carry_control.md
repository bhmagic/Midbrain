# Grip and Carry Control

Version: 0.1 working draft

The Grip Provider owns only the gripper actuator group, its background 50 Hz command stream, grip-contact inference, the conservative task temperature gate, and runtime attachment identity. Contact owns only arm Cartesian contact motion and the arm group's position/effort hold. Basic remains the sole motor transport and feedback owner.

The owner-confirmed joint convention is that more-negative gripper positions
open the reBot gripper. The effector profile records `-280` degrees as the fully
open physical endpoint and `-180` degrees as the functional-open threshold used
for approach readiness; the owner-observed normal-object endpoint closes toward `+12` degrees while Basic enforces `+17` degrees as the absolute close limit. A
Skill may request a signed `SET_MIT_POSITION` opening while Integrated moves the
disjoint six-joint arm group. Grip interpolates the measured joint-7 position
at 50 Hz for at least 1 second, extends that time when necessary to preserve
the owner-requested attended-development 4 rad/s cap, and holds the endpoint in
MIT. This value exceeds the official reBot application 3 rad/s setting and is
not autonomous physical qualification. Approach readiness
requires fresh below-gate temperature feedback plus measured functional
openness. The Skill must recheck temperature readiness when physical Stage 1
begins rather than relying only on an earlier preview.

A new grip is rejected when any installed active joint has missing, stale, non-finite, or at-least-85-C temperature feedback. The response supplies a simple retry delay. This is an owner-requested attended-development task admission gate below hardware safety limits; it does not inhibit unrelated arm motion. A hot joint while carrying never causes an automatic drop: both Providers retain `POSITION_EFFORT_LIMITED` and publish a release recommendation.

Carry confirmation requires all of the following: a finite Contact v2 `PREPARE` plan has settled; the gripper has inferred stable contact; Contact has bound the carry ID and attachment revision; and Basic reports every active joint in `POSITION_EFFORT_LIMITED`. By default, confirmed-carry movement uses Contact v2 `CONTINUE`; free-space movement and MIT float are invalid, and idle is the last Contact position/effort target plus the persistent gripper position/effort target. Lay Flat is the one declared exception: its initial two-vector rotation uses the same Integrated rotation-only, verified-`FLOAT`, Integrated-`WARM` handoff as Slicing before Contact resumes the placement. This exception means uninterrupted all-joint POS_TOR is not claimed during Lay Flat alignment.

The generic `grip.grip` Skill performs no approach motion. It requests the task-facing Grip Provider once, reads Contact's measured acting-frame pose, submits one signed zero-displacement Contact v2 `PREPARE` step preserving that measured orientation, and only then closes the gripper. This measured-pose acquisition is required before carry confirmation; closing the gripper alone never proves the all-joint carry invariant. The default current-pose and Scrap Grip close commands request the owner-requested attended-development 4 rad/s Provider cap and permit 10 seconds for stable contact. Basic retains a 0.75 native FORCE_POS translation, so the close sends a 3 rad/s native motor ceiling. Closing from the functional `-180` degree threshold toward the `+12` degree endpoint therefore requires about 1.12 seconds before contact and stable-sample time. Contact is inferred only when absolute measured gripper-motor torque remains at or above `0.15` N m for 10 consecutive 50 Hz samples; position and velocity remain diagnostics and do not decide contact. If stable contact is not confirmed, the Skill must open to the functional threshold, verify measured openness, transition the gripper to MIT float, relax Contact, and return an explicit unsuccessful terminal result without creating a carry. Soft or thin objects require a separate qualified Skill.

The compatibility identity `grip.grip_object` remains the two-vector approach Skill while its user-facing label is `Action: scrap grip`. `grip.grip` is the separate user-facing `Action: grip`. Scrap Grip and Lay Flat own numbered task-use gripper-vector profiles separately from their motion profiles. A task-use vector profile does not replace the mounted-effector identity or Grip Provider control profile: the active mounted-effector revision and grip-control compatibility gate remain authoritative. An Agent Scrap Grip request may explicitly mark its approach begin value `RELATIVE_TO_CURRENT_EFFECTOR_WORLD`; the Skill itself captures current measured Integrated FK during preparation and resolves the supplied world-axis offset. The Agent must not substitute an RGB/VLM effector point for that measured origin.

Scrap Grip and Lay Flat strongly follow Slicing's controller split in both regular and developer execution. Integrated Stage 1 is rotation-only: its target position is the measured current controlled-effector position, its orientation is the frozen two-vector result, and its accepted path must complete in verified `FLOAT`. Before Contact activation, the Skill revalidates calibration and identity-bound FLOAT evidence, moves Integrated to `WARM`, and verifies that Integrated's Basic lease is inactive. Contact's first move is `ABSOLUTE_ROOT`; subsequent insertion or retreat displacement is measured-start-relative. Scrap Grip's absolute target is approach begin plus table inward. Lay Flat's absolute target is approach begin plus table inward and negative insertion. The developer pages accept absolute active-world or current-effector-relative approach entry and freeze relative input from the measured Integrated origin during preparation. The shared runtime waits for each Contact trajectory to finish before starting the profiled lower or scrap dwell. Scrap Grip starts its grip dwell only after stable torque contact is inferred; Contact remains mode-guarded and holding throughout closing, contact dwell, settling, and carry confirmation. Lay Flat marks its Stage 1 confirmed-carry POS_TOR exception in the plan and UI.

Release first opens the gripper under `POSITION_EFFORT_LIMITED`, including when hot. After measured opening, a separate signed request supplies MIT gains and delta time. The Grip Provider interpolates at 50 Hz, clears its Basic mode guard, enters Basic gripper-group gravity float, and releases the group lease. When a carry is confirmed, Let Go clears that attachment and relaxes Contact. When no carry is bound, the same user action performs only the gripper open-and-float path and does not acquire or relax Contact.

Object presence inferred from stable absolute measured motor torque is not object identity. A finite Skill must bind an explicit runtime attachment revision. Payload and collision geometry may be absent during development, but no component may claim collision-safe free-space carrying without qualified attachment geometry.

Except for the declared Lay Flat Integrated alignment interval above, the all-joint position/effort invariant applies throughout a valid confirmed-carry authority lifecycle, including idle. Basic's existing emergency inhibit, expired-lease fallback, hardware-fault handling, and deadman rules remain authoritative; a Provider must not preserve unowned torque indefinitely after those safety boundaries fail.
