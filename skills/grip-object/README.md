# Action: scrap grip

This finite Skill aligns two effector-frame directions to two object/world directions. Like Slicing, Integrated performs only a collision-checked rotation at the measured current position and finishes in verified `FLOAT`. Concurrently, the independently leased Grip Provider interpolates joint 7 at 50 Hz to the functional `-180` degree open threshold and holds it in MIT. Stage 1 completes only after fresh below-85-C temperature readiness and measured functional openness. The Skill then confirms Integrated is `WARM` with no arm-group Basic lease before Contact becomes `HOT`; Contact moves to the absolute approach-begin-plus-table-inward target and performs relative insertion. For normal objects, the Skill closes toward the owner-observed `+12` degree endpoint and binds a runtime carry only after Contact settling, absolute measured gripper-motor torque remains at or above `0.15` N m for 10 consecutive 50 Hz samples, and all-seven-joint `POSITION_EFFORT_LIMITED` confirmation. Position and velocity remain contact diagnostics only. Without stable contact it opens and floats the gripper, relaxes Contact, and returns `FAILED_TO_GRIP`; soft or thin objects require another Skill.

The stable internal identity remains `grip.grip_object` and the Agent tool remains `grip_object` for compatibility. The user-facing name distinguishes this table/insertion scraping approach from the separate generic `Action: grip` Skill.

The Skill owns its motion and gripper-vector profile configuration plus its `.venv`. Its Slicing-style developer UI edits numbered vector and motion defaults, exposes all gripper/object vectors, and freezes one attended four-stage session. The approach-begin entry may be an absolute active-world point or a world-axis offset from the current controlled effector. Relative mode captures the measured Integrated effector origin during preparation and publishes both that origin and the resolved frozen point in the session. The regular Agent path supports the same explicit mode and captures the same measured FK itself; it never needs a VLM effector point for “current IK.” A zero relative offset preserves the Contact approach origin but still applies the orientation frozen from the two vector pairs. Stage 0 and the start of Stage 1 both check current Grip thermal readiness. Stage 1 starts the gripper's signed 50 Hz MIT opening and commits the rotation-only Integrated preview while that independent transition runs; it then requires verified `FLOAT`, measured gripper approach readiness, moves Integrated to `WARM`, verifies the arm-group Basic lease is inactive, and activates Contact. The requested transition time is 1 second, extended only when necessary to preserve the owner-requested attended-development 4 rad/s cap. Stage 2 submits an `ABSOLUTE_ROOT` Contact target equal to the approach-begin point plus the table-inward offset, waits for Contact's trajectory-complete observation, then applies the profile's `delay_after_lower_s`. Stage 3 submits relative insertion, waits for trajectory completion, then applies `delay_after_scrap_s`. Stage 4 requests the same 4 rad/s physical cap; Basic's retained 0.75 native FORCE_POS translation sends a 3 rad/s motor ceiling. It first requires stable torque contact and then applies `delay_after_grip_s` while the gripper and arm remain in guarded position/effort hold. All three waits default to 1.5 seconds and are used by both regular Agent and attended development execution. Contact-runtime waits continue servicing authority. The Skill allows 10 seconds for stable contact and closes toward `+12` degrees, below Basic's separate `+17` degree absolute close limit. This exceeds the official reBot application 3 rad/s setting and remains physically unqualified. If contact is absent, the page displays the explicit failed-grip message and ends the session after verified release instead of leaving it pending. Every physical stage requires a separate operator acknowledgement. The existing host authorization API signs the Integrated commit without language-model reasoning or an Agent source modification.

Agent calls provide the target object's stable identity as
`object_binding.object_id`. This field identifies the object for the runtime
attachment; it does not replace the independent physical-contact inference.
